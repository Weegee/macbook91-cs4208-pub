Structure version: 20261021.01

Layout rules for this repository. The README describes the same directories
for a reader; this file is the rule.

src/cs420x-a1534/   the DKMS module. This directory is what ships: it is
                    copied verbatim to /usr/src/macbook91-cs4208-<pkgver>,
                    so nothing may live here that must not reach a user.
                    It TRACKS only what this project wrote: its
                    own headers, the patches describing its changes to kernel
                    code, and its documentation. No kernel source file is
                    tracked here. The upstream-derived half of the tree -
                    <series>/cs420x.c, upstream/<series>/, kheaders/<series>/ and
                    vendored/a1534_sequence.h - is generated by
                    packaging/fetch-upstream.sh and gitignored, and
                    packaging/upstream.lock is the record of what those bytes
                    must be. A (tag, file) pair the lockfile does not know is
                    refused; one it knows and that has changed is a hard
                    failure with no override.
                    vendored/ORIGINAL-a1534_sequence.h is the exception, and
                    is not one of kernel code: it is the vendored upstream verb
                    sequence, it is tracked permanently,
                    Git is its integrity record, and it is never fetched from
                    anywhere.
tools/              measurement and diagnostic tools, development-side.
                    macbook91-audio-verify is the exception - it is packaged
                    to /usr/bin by the root Makefile's install target.
tests/              hermetic regression tests: no root, no hardware, no sound.
Makefile, VERSION   the package contract: `make dist` writes the
                    reproducible source tarball dist/NAME-VERSION.tar,
                    `make install` is what package() runs from it, `make
                    arch-pkg` builds a release against the pinned checksum.
                    VERSION is the single version; the PKGBUILD's pkgver and
                    the release tag v<VERSION> must equal it. It has the form
                    YYYYMMDD.NN, like the maintainer's other packages (the
                    earlier numbering: end of docs/CHANGELOG.md).
LICENSE, LICENSES/  since 20261020.02 LICENSE is the GPL-3.0 text and
                    LICENSES/ holds the texts of the other licenses used
                    here, one file per SPDX identifier; the source tarball
                    carries every text its files need. README.md's
                    "Provenance and licensing" maps every path to its
                    license; a file that can carry a comment names its own
                    on an SPDX-License-Identifier line.
packaging/          the scripts that fetch (fetch-upstream.sh), write the
                    source tarball (mkdist.py) and promote, plus
                    make-package.sh, a wrapper for `make arch-pkg-dev`.
                    upstream.lock is tracked: it is the provenance record for
                    everything fetch-upstream.sh assembles, and it is
                    promoted into release/<pkgver>/ with the rest.
packaging/arch/     PKGBUILD, .SRCINFO and the install scriptlet. Not part of
                    the source tarball, which is what lets the PKGBUILD pin
                    the tarball's checksum.
dist/, build/       gitignored output: tarball and packages, and the makepkg
                    work area build/arch, recreated for every build.
release/<pkgver>/   promoted releases: the PKGBUILD, source tarball, install
                    scriptlet and status note exactly as published. The built
                    .pkg.tar.zst is NOT tracked and is not copied here: it
                    stays in dist/, and the release assets are exactly the
                    tracked files of this directory. Retain the current
                    release and the one before it;
                    older releases are not part of this repository.
                    promote-release.sh prunes the rest once the new release is
                    written and sealed, and names every directory it removes -
                    this rule was kept by memory for twenty releases and then
                    by hand once, which is not a rule.
                    The tracked source tarball is a complete, assembled tree
                    and so does contain kernel code. That is a decision, not
                    an oversight: a promoted release has to stay buildable
                    from itself, with no network and without kernel.org still
                    serving the tag it was cut at. "No kernel code in the
                    repository" governs what is maintained here, not what a
                    published artifact carries.
docs/               the investigation notes and the machine-readable test
                    status.

Paths that exist only in the maintainer's own checkout (agent configuration,
local evidence, code-graph caches) are not part of the published tree and are
not described here.

Early notes may say work/src, work/tests, work/tools or work/pkg: those are
the old names of src, tests, tools and packaging.
